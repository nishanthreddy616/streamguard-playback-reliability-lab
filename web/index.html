How the request is checked

Each stage adds an access or delivery check.

RequestPlayback APICheck JSON size and fields
AccessEntitlementCheck membership and video rights
DeviceProtection policyCheck region and DRM support
DeliveryEdge selectorEstimate latency and recover from failure
GrantSession tokenSign a short-lived demo grant

For a production system, replace the in-memory demo catalogs and counters with owned identity, rights, and telemetry services; use key rotation and a managed signing key; keep the player and license service boundaries explicit.

Security boundary

The API issues only a short-lived demo session grant after policy checks. There is no DRM license server, real playback URL, personal data, or production key material.

Reliability exercise

Inject a preferred-edge failure and follow the recovery path. The request keeps its access decision while the router picks another healthy edge and exposes the added latency.

  -H 'content-type: application/json' \
  -d '{"member_id":"member-active","asset_id":"catalog-alpha","region":"us-west","drm":"Widevine","preferred_edge":"edge-west","latency_profile":"healthy","simulate_edge_failure":true}'
